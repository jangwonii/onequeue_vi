# 우리의 약속 운영

## 배포와 인증
- 새 서비스 ID: appgprj_6ad1aef6c6a4819197a170482eddef2e. 기존 SEVEN과 DB·소스를 공유하지 않는다.
- 실제 운영 인증은 Sites의 ChatGPT 로그인 경계에서 전달한 신원만 사용한다. 공개 경로는 소개 화면과 상태 확인뿐이다. 사용자 설정·방·기록은 로그인 후 권한을 확인한다.
- 로컬 통합 테스트는 루프백에서만 테스트 헤더를 사용한다. 이 결과는 실제 운영 로그인 검증과 구분한다.
- DB는 Sites D1, 본문·로그에 이메일·인증 토큰을 저장하지 않는다. 예기치 않은 오류는 요청 ID와 오류 종류만 기록한다.

## 검증 명령
- node --test tests/domain.test.mjs
- node scripts/verify-build.mjs
- node tests/integration.mjs
- node tests/quality.mjs
- 원큐 v0.3에 domain·integration·quality 실행 사례 보고서를 등록한다. 모바일 다운로드와 시간 경계 화면 갱신은 같은 사례 안에서 각각 함께 검증한다.

Sites 빌드 도우미는 이 Windows 환경에서 npm shim 경로 오류가 발생했다. 같은 프로젝트 빌드 스크립트를 Node로 실행하는 verify-build를 사용한다. 설치 및 빌드 성공 후 소스 도우미는 이미 확인한 결과를 commands: []로 패키징한다.

## 상태 확인과 장애 대응
- GET /api/health는 D1 읽기 성공, 릴리스, 배포 소스 해시를 반환한다.
- 반환 release와 buildHash를 해당 배포 소스의 lib/build-info.mjs 및 버전 영수증과 대조한다.
- 오류 시 사용자 요청 ID와 Sites Worker 로그를 대조한다. 토큰과 사용자 본문을 로그에 추가하지 않는다.
- 권한 오류는 재로그인과 해당 방 참여 여부를 확인한다. 동시 수정 충돌은 새로고침 후 재시도한다.
- 계정 삭제는 deleting 상태를 먼저 저장하여 신규 쓰기를 막는다. 삭제 도중 오류가 나면 같은 확인 문구로 다시 실행해 마무리할 수 있다.
- 인증 신고는 48시간 미처리 후 자동으로 원래 인증을 유지한다. 읽을 때와 다음 쓰기 때 서버 시각으로 계산하므로 예약 작업이 없어도 결과가 멈추지 않는다.

## 마이그레이션과 복구
- db/schema.ts 변경 후 npm run db:generate. 기존 SQL 수정 대신 다음 번호의 마이그레이션을 추가한다.
- 배포 패키지의 drizzle SQL은 Sites 배포 과정에서 적용한다. 배포 후 live DB overview로 테이블을 확인한다.
- 파괴적인 스키마 변경은 데이터 내보내기와 별도 복구 검증 후 수행한다. 앱 롤백만으로 DB 스키마가 되돌아간다고 가정하지 않는다.
- tests/integration.mjs는 실제 로컬 D1 저장소의 일관된 SQLite 백업을 만들고 별도 DB에서 방·참여자·인증 수와 쓰기 가능 여부를 확인한다.
- test-results의 백업은 가상 테스트 데이터뿐이며 배포하지 않는다.
- 운영 DB는 Sites 관리 영역에 있다. 현재 연결 도구는 운영 DB 조회만 지원하며 임의 SQL 복원·예약 백업 실행을 제공하지 않는다. 따라서 운영 전체 DB의 자동 백업/복원은 검증 완료로 주장하지 않는다. 서비스 확장 전 운영자가 지원되는 DB 관리 경로와 보관 정책을 확정해야 한다.
- 사용자는 앱에서 자기 기록 JSON을 언제든 내려받을 수 있다. 이 파일은 개인정보 열람용이며 전체 운영 DB 복원 파일이 아니다.

## 용량과 범위
- 방당 2~10명, 계정당 소유 방 30개, 방당 최대 104시즌, 문서 150만 문자 제한.
- 한 사용자에게 분당 120회 변경 요청 제한. 대규모 공개 서비스의 비용·남용 제한은 별도 운영 검토가 필요하다.
- 인증은 텍스트 수행 기록·타이머·사진을 사용한다. 사진은 클라이언트에서 최대 1280px로 재인코딩해 메타데이터를 제거한다. 서버는 JPEG/PNG 헤더·최대 512KiB를 검증하고 R2 BUCKET에 저장한다. 사진 URL은 현재 친구방 참여 권한을 검사하며 공개 R2 URL을 발급하지 않는다.
- 계정 삭제는 삭제 상태를 먼저 기록하고 사진을 지운 다음 DB 개인정보를 제거한다. 저장 충돌의 미연결 사진은 요청 실패 시 정리한다. 정리 실패는 요청 번호와 함께 photo_cleanup_failed로 기록하며 별도 운영 정리가 필요하다. 운영 R2 전체 백업/복원은 아직 검증하지 않았다.
- 개인 JSON에는 본인의 사진 접근 경로가 들어간다. 사진 원본은 피드의 사진 저장으로 내려받는다. 탈퇴·삭제 후에는 해당 접근 경로를 사용할 수 없다.
- 추가 실천은 하루 3개까지이며 공식 점수와 분리한다. 친구 알림은 수신자 기준 이 방 하루 2회, 수신 설정은 방별로 유지된다. 외부 푸시·결제·예치·리그는 제공하지 않는다.
- 운영 DB에는 데모 신원이나 날짜 변경 기능을 두지 않는다. 둘러보기는 메모리에만 있는 화면 예시다.

## 실패 트리거와 사진 필수 · v2.2
- 새 공식 인증은 과거 사진 선택 목표를 포함해 사진을 요구한다. 기존 저장 인증은 그대로 유지한다. 추가 실천은 사진 선택이며 점수와 실패 조건에 영향을 주지 않는다.
- 트리거 설정은 방장만, 시작 전만 가능하다. 전원 동의에는 현재 agreementVersion과 acceptTrigger가 필요하며 조건 변경 뒤 오래된 화면의 동의는 거절된다.
- 판정 대기는 미달 벌칙에 넣지 않는다. 상금과 시즌 미완주 벌칙은 인증 검토가 끝난 뒤만 산출한다. 정산 항목은 시즌·대상·실패일로 결정해 새로고침이나 동시 요청으로 중복 발동하지 않는다.
- 상금은 미완주자 각자의 약정액을 완주자에게 직접 나누어 송금하는 모델이다. 보관된 잔액이나 결제 완료 사실을 주장하지 않는다. 당사자가 송금 신고하고 수령자가 확인한다. 벌칙은 당사자의 이행 신고 후 다른 참여자가 확인한다.
- 계정 삭제 시 관련 시즌은 triggerSuspended를 기록하여 자동 재배분과 새 정산 확인을 중단한다. 이미 이루어진 실제 송금은 앱이 환불할 수 없으며 친구들이 직접 확인해야 한다.
- 기록 확인만으로 금융 서비스 운영 적합성이나 사진 진위를 검증한 것은 아니다. 운영 로그인과 D1/R2 전체 복구는 별도 미검증으로 유지한다.
- 통합 검증의 과거 정산 시즌은 로컬 격리 D1에만 합성 자료로 넣고 테스트 종료 시 정리한다. 운영 시각·데이터 변경 기능은 추가하지 않는다.
